🔫 Прокачка — фиксированная

1 буст на уровень. Уровни 1–4 добавляют пушки (до 5), уровни 5–10 удваивают урон. Эффект сохраняется и накапливается весь забег (сбрасывается только при смерти).

👾 Сколько боссов на уровне

Чередование 1 / 2, тройка только на финале. Все боссы уровня появляются разом — уровень зачтён, когда убиты все.

📦 Типы боксов

Много боксов, падают быстро (+20%, ещё +8%/уровень). Стреляй по синим, красные пропускай.

🎟 Награды — билеты раз за уровень

Билет разыгрывается один раз при закрытии уровня (не с каждого босса). Ранние уровни — по шансу, поздние — гарантированно.

📊 Уровни и стоимость

HP указан за одного босса (как на экране игры). Всего на волну = HP/босс × число боссов. Выстрелы = HP ÷ урон. Внизу — сколько MP уходит за всю игру.

🧩 ТЗ для интеграции в систему лояльности

Цель: встроить Hash Blaster как мини-игру внутри сайта/личного кабинета ECOS Loyalty, где MP — реальная валюта лояльности, а билеты начисляются только после серверной валидации забега.

1. Точка входа

  • Игра открывается из раздела Loyalty по кнопке Play Hash Blaster.
  • Перед стартом фронт запрашивает у backend актуальные userId, mpBalance, runNonce, лимиты дня и конфиг экономики.
  • Если у пользователя недостаточно MP для старта, игра не запускается: показать экран пополнения/заработка MP.

2. Сервер — источник правды

  • Клиент не должен сам финально списывать MP или начислять билеты. Он только отправляет события забега.
  • Backend считает итог: сколько MP потрачено на выстрелы, сколько MP получено с синих блоков, сколько билетов заработано, сгорели ли билеты при смерти.
  • Все правила баланса должны лежать в одном конфиге на сервере: bossHp, bossesPerLevel, powerCurve, ticketRules, стоимость выстрела.

3. Минимальные API

{
  "GET /api/loyalty/hash-blaster/config": "вернуть баланс v2 и публичную версию конфига",
  "POST /api/loyalty/hash-blaster/runs/start": "создать runId, runNonce, зафиксировать стартовый MP",
  "POST /api/loyalty/hash-blaster/runs/{runId}/events": "батч событий: shot, box_hit, boss_hit, level_clear, death, bank_exit",
  "POST /api/loyalty/hash-blaster/runs/{runId}/finish": "сервер валидирует забег и возвращает финальный MP/tickets"
}

4. События, которые игра отправляет

  • shot: время, уровень, координаты, цена 1 MP.
  • box_hit: тип блока, награда/штраф MP, позиция, timestamp.
  • boss_hit: уровень, bossIndex, урон, оставшийся HP.
  • level_clear: уровень, результат roll билетов, текущие билеты забега.
  • death: причина смерти, достигнутый уровень, билеты к сгоранию.
  • bank_exit: пользователь забрал билеты после завершения уровня.

5. Правила экономики v2

  • Стоимость выстрела: 1 MP.
  • HP боссов по уровням: [150, 110, 250, 1400, 20000, 100000, 500000, 1000000, 6000000, 5500000].
  • Количество боссов: [1, 2, 1, 2, 1, 2, 1, 2, 1, 3].
  • Билеты начисляются один раз за уровень. До банковки они находятся под риском: смерть сжигает билеты текущего забега.
  • Bank & exit доступен только на экране завершения уровня. После банковки билеты становятся постоянными.

6. Античит и ограничения

  • Каждый забег подписывать через runNonce; повторный finish для одного runId запрещён.
  • Сервер проверяет невозможные значения: слишком много выстрелов в секунду, отрицательные траты, урон выше power curve, пропущенные уровни.
  • Хранить полный журнал итоговых событий минимум для спорных забегов и топовых результатов.
  • Добавить дневные лимиты по забегам/билетам, чтобы игра не ломала экономику лояльности.

7. UX в реальной системе

  • В HUD показывать реальный MP-баланс пользователя и билеты забега отдельно от уже сохранённых билетов.
  • На вебе игра должна отображаться в телефонном контейнере, а не растягиваться на весь экран: рекомендуемый viewport 390×844, максимум около 430px по ширине, центрирование на десктопе.
  • Dev-панель нужна только для QA и демонстраций. В проде её убрать полностью или включать только через защищённый debug-флаг, недоступный обычным пользователям.
  • После завершения забега показывать серверный итог: MP списано, MP найдено, чистый расход, билеты начислены/сгорели.
  • Если MP закончились во время забега, игра ставится на паузу и показывает выбор: Забрать награду или Докупить MP.
  • Кнопка докупки должна вызывать магазин через window.ECOSHashBlaster.openMpShop(). После успешной покупки магазин возвращает количество добавленных MP, игра снимает паузу и продолжает с того же момента.
  • При потере сети ставить игру на паузу и не позволять завершить забег без синхронизации с backend.
